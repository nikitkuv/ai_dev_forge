# Детерминированная автоматизация Forge

Инвентаризация и реализованные дополнения: 2026-09-22. Исходный framework bundle не является проектом-потребителем; проверки lifecycle выполняются на изолированных fixtures. OpenSpec для этих изменений не используется.

## Уже существовавшие операции

| Участок | Команды | Механическая работа | Что остаётся суждением |
| --- | --- | --- | --- |
| Контекст | context, section, query, index, budget | Metadata, извлечение разделов, поиск, оценка объёма | Выбор релевантных источников |
| Идентификаторы | next-id, inv-create, backlog add-bug | Максимум номера, создание INV/BUG | Содержание и необходимость записи |
| Валидация | validate | Схема, часть ссылок, статусы, adapters | Семантика требований и полнота evidence |
| Evidence | fingerprint, evidence-check, review-packet | Хеши, свежесть, diff, сборка пакета | Классификация production, риски, качество review |
| Проверки | checks-new, checks | argv, запуск, timeout, логи, проверяемый reuse | Какие проверки достаточны |
| Lifecycle | transition, epic-start/complete, accept-record | Запись переданных решений с rollback | Авторизация и приёмка |
| Backlog | update-row, archive-row/all, stale-rows | Ячейки, архивирование, Git-давность | Приоритет и решение закрыть работу |
| Git | commit-scoped | Ограниченный staging/commit | Смысл изменений и разрешение |

| Метрики | metrics-record, metrics | Запись и агрегация переданных наблюдений | Ранее большинство записей готовил агент |

## Добавленные операции

- `identity-check`: точные структурированные рассогласования и byte hashes для записи без повторного ручного сканирования. Основные проверки встроены в `validate --project`.
- `records-write`: пакетная запись подготовленного содержимого с единым отображением символических ID, проверкой текущих входов, общим transaction guard и rollback. Новая сессия не должна исправлять частично сохранённый пакет.
- `links-repair`: preview/apply однозначных исправлений отсутствующих Markdown-целей; конфликтующие ID не угадываются.
- `records-recover`: восстановление общего lifecycle-журнала.
- Epic Start/Complete сохраняют актуальные inline Markdown-ссылки при перемещении workspace в рамках той же транзакции.
- `checks --task` и `role --task`: автоматическая запись измеримых наблюдений, usage только при наличии данных провайдера.
- Расширенная сводка метрик: review iterations, role calls, ожидание, повторное использование проверок, причины эскалации, известные исходы и неизвестные значения.

## Что предотвращает ошибки ID

1. Модель готовит содержание с символами `{{id:first}}`, а не копирует очередные номера между файлами.
2. Одна операция подставляет номера в имена файлов, frontmatter, заголовки, зависимости и план.
3. Сохранённая другой сессией запись инвалидирует preview. Повторный `next-id` сам по себе номер не резервирует.
4. После записи проверяется согласованность всего состояния, при ошибке восстанавливаются прежние файлы.
5. Восстановление сессии потребляет готовую диагностику. Проверка перед передачей сессии обнаруживает проблему раньше.

Система проверяет объявленные структурированные поля и простые inline Markdown-ссылки, а не произвольный текст. ID требований FR/NFR/BR и локальные AC/TC — другие пространства имён. Исторические ссылки архива не являются активными зависимостями. Полного семантического анализа или автоматического выбора «правильного» ID здесь нет.

## Дальнейший выбор работ

Самые рискованные механические места закрыты первым набором: пакетное сохранение и обнаружение рассогласований. Остальные операции из первой таблицы уже имеют helpers: дублировать их новой модельной ролью не нужно. Следующие кандидаты следует выбирать по собранным данным:

- какие workflows обходят существующие helpers;
- какие результаты проверок агент повторно переписывает в evidence;
- какие дополнительные форматы проектных ссылок действительно вызывают проблемы;
- какие provider/runtime возвращают достоверный usage для native calls.

Повторяющаяся ошибка оформляется как воспроизводимый случай и исправление её причины: код и regression test для механики, точечная правка нейтральной инструкции для суждения. Автоматически растущей памяти ошибок нет. Evals и автоматический CI-triage остаются отложенными.
