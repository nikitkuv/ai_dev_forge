# Проверка пользы памяти на новых сессиях

Механическая проверка: `python tests/evaluate_agent_knowledge.py`. Она создаёт изолированные проекты, вызывает настоящий поиск и knowledge-check и сверяет результаты с независимыми ожиданиями. Она не запускает модель и не оценивает выполнение агентом инструкций.

## Сравнение A/B/C

Источник сценариев и критериев: `tests/fixtures/agent-knowledge.json`. Исходный framework зафиксирован ревизией `2cca4d8812bdf8aaa6da773563116d9ee5e7c81f`. Для A используйте копию bundle этой ревизии; для B/C — bundle проверяемой ревизии. Не меняйте рабочий checkout ради baseline: экспортируйте соответствующую `.ai/` из Git в отдельный временный каталог.

1. Для каждого сценария, варианта и повтора создайте отдельный пустой проект: `python tests/evaluate_agent_knowledge.py --prepare <empty-project> --case changed-dependency --variant B`. Сохраните JSON из stdout как карточку эксперимента вне проекта агента. Скрипт отказывается перезаписывать непустой проект. Все варианты получают одинаковую историю; различаются только framework и консолидация.
2. Поместите нужный bundle в проект, настройте одинаковые platform/model/effort и native_subagents для всех сравниваемых запусков. Сгенерируйте адаптеры штатным preview/apply. Не запускайте product bootstrap и не подменяйте fixture-факты. Укажите точную ревизию bundle, модель и параметры в `settings` карточки; не выдавайте агенту oracle/rubric или результаты других вариантов.
3. A выполняет назначение с прежними workflow. B — с bounded retrieval и проверкой применимости. C сначала получает отдельную новую сессию с запросом консолидации выбранных fixture-записей, в пределах 20 источников. Сохраните её предложения как экспериментальное evidence вне agent workspace. Если есть конкретные корректировки знаний, примените только разрешённые экспериментом изменения TASK/INV по существующему workflow с сохранением происхождения, затем закройте сессию. Не редактируйте baseline/oracle и не меняйте инструкции агента вне проверяемого bundle.
4. Для каждого основного запуска откройте новую сессию без transcript/resume/global memory прошлых попыток. Передайте только `ASSIGNMENT.md` и путь проекта. Не переносите разговор консолидации в C: доступен только сохранённый результат в файлах проекта. Зафиксируйте подтверждение fresh session в evidence.
5. Независимо оцените результат по `rubric`: правильность, harmful reuse, повторение ошибки и ненужное исследование. Запишите фактически прочитанные и использованные источники из наблюдений. Вызов query сам по себе не доказывает чтение. Сохраните краткое evidence, не секреты и не весь приватный transcript.
6. Заполните карточку и проверьте `python tests/evaluate_agent_knowledge.py --trial <trial.json>`. Для measured обязательны model/settings/trial/evidence_ref/fresh_session, boolean quality_pass/harmful_reuse и observed source lists. Недоступные usage и длительности остаются null, не нулём. Для C отдельно учитывайте стоимость и время консолидации, включая применение поправок.
7. Используйте не менее трёх повторов каждой доступной пары scenario/model/variant; при меньшем количестве покажите ограничение. Сравнивайте только одинаковые case/model/settings и отдельно показывайте A/B/C, размер выборки, долю ошибок, harmful reuse и полную известную стоимость. Не объединяйте разные модели. Не утверждайте улучшение по одному примеру или только по сокращению контекста. Регрессии на changed-dependency/canonical-conflict должны быть разобраны до расширения автоматической подгрузки памяти.

Запуски моделей выполняются только при доступном авторизованном runtime и бюджете. Если их нет, механические тесты выполняются, а агентные исходы и стоимость явно остаются `unmeasured`. Это ограничение измерения, а не успешный результат агента.

## Наблюдение при реализации change

Механические результаты сохраняются в `tests/fixtures/agent-knowledge-mechanical-result.json`. A/B/C сравнения агентов не запускались: отдельный runtime/model/budget эксперимента не был задан. Польза для моделей, качество выбора источников и стоимость консолидации остаются неизмеренными.
