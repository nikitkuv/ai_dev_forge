AI Development Forge · сценарий 02

Существующий проект:
безопасная миграция в canonical-процесс

Здесь фреймворк сначала понимает уже существующий код и документы. Он не переписывает историю и не маскирует неопределённость автоматическими решениями.

АнализЯвное согласованиеCanonical-документ
Вход

1. Явный bootstrap existing

Оркестратор убеждается, что открыт проект-потребитель, а не репозиторий фреймворка; читает правила и Git status.

src/tests/legacy docs
Preflight

2. Конфигурация и collision check

Фиксируются платформы, модели, политика Git; существующие target-файлы не перезаписываются без понятного diff.

.ai/project.yaml
Context

3. Сбор наследия

Код, тесты, история и документы становятся evidence. Неуверенность сохраняется как вопрос, а не как выдуманный факт.

Migration

4. Контекст → проектные draft

Собранные факты разделяются на product behavior, архитектуру, решения и roadmap.

SPEC.mdARCHITECTURE.mdBACKLOG.md
Approval

5. Migration diff

Пользователь отдельно видит предлагаемые файлы, конфликтующие места и пробелы контекста — и подтверждает только понятные изменения.

Sync

6. Canonical state и adapters

После approvals создаются/обновляются ADR, index решений и адаптеры Codex/Claude.

DECISIONS.mdframework.lock
Verify

7. Validation → READY

Проверяется согласованность документов, адаптеров и репозитория. Код сам по себе не меняется.

Защитная ветвь: collision, недостаток evidence или неоднозначный legacy-контекст останавливают миграцию на этапе уточнения. Продолжение требует ответа пользователя, а не предположения агента.

Результат: прошлое проекта остаётся проверяемым источником контекста, а дальнейшая работа начинается только из утверждённого canonical-состояния.
