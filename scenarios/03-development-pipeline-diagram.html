Полный pipeline:
одна TASK за раз

Разработка движется доказательствами: реализация, независимый review, тестирование и явная приёмка — это разные состояния с разными полномочиями.

TASK stateРоль агентаПользовательский gate
Task Start

TODO

Пользователь явно запускает одну конкретную TASK из утверждённого плана.

implementer

IN PROGRESS

Изменяет production-код и тесты строго в scope TASK. Сохраняет evidence.

strong reviewer

IN REVIEW

Проверяет реализацию независимо. Чистый review открывает тестирование.

tester

IN TESTING

Запускает focused, selected affected и scoped checks; tester не пишет production-код.

Task Acceptance

AWAITING USER ACCEPTANCE

Пользователь проверяет результат; исправления в scope возвращают работу в реализацию.

Принято

DONE

Только явная приёмка завершает TASK. Следующая не стартует автоматически.

↩ Review findings
IN REVIEW → IN PROGRESS → новый review.
↩ Test failure
IN TESTING → IN PROGRESS → review и selected checks повторяются.
↩ Новый scope
AWAITING USER ACCEPTANCE → Replan gate → новая/изменённая TASK.

Когда последняя TASK Epic принята

Все TASK · DONE→VALIDATING · full regression→FUZZING · read-only→Epic Acceptance→BACKLOG: COMPLETED

Validation или fuzzing findings создают remediation TASK через replan; проблема на Epic acceptance возвращает Epic в ACTIVE. После изменений validation и fuzzing повторяются. Следующий approved workspace остаётся в execution/planned и запускается только отдельным Epic Start.

Новая feature

Intake → уточнение → PLANNED/OUTLINE Epic → approvals. Активная TASK не меняется.

Новый bug

Intake → reproduction → BUG только для принятого кода → scheduling через TASK.

Reprioritization

Dependency graph показывает блокировки; порядок меняется лишь после ответа пользователя.

Pause / resume

Согласованная пауза сохраняет gate и перемещает Epic; resume требует явного разрешения.

Security audit

Только явный запрос. По умолчанию local, read-only, без сети и установки инструментов.
