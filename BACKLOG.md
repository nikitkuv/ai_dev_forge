## Epic Details

### EPIC-001 — Code Review Agent

**Problem:** Код, написанный AI-агентом в рамках таски, не проходит ревью перед переходом к следующей таске. Ошибки и bad practices накапливаются в рамках эпика.

**Solution:** После завершения каждой таски (статус `DONE`) автоматически запускать отдельного субагента-ревьювера. Субагент использует сильную модель (например, Opus/Sonnet вместо Haiku) и проверяет:

- соответствие ARCHITECTURE.md
- соответствие CONVENTIONS.md
- наличие потенциальных багов
- качество кода (читаемость, именование, структура)
- покрытие acceptance criteria из TASK.md

**Результат ревью:** отчёт сохраняется в `execution/active/EPIC-NNN/tasks/TASK-NNN-review.md`. Если найдены критические замечания — таска возвращается в `IN PROGRESS` с комментариями.

**Границы:**
- Ревьюер — отдельный субагент, не основной агент-исполнитель
- Модель рьюёра должна быть сильнее модели исполнителя
- Ревью не блокирует переход к следующей таске, если замечания не критические
- Формат отчета ревью определяется шаблоном

### EPIC-002 — Fuzzing Test Runner

**Problem:** После завершения эпика нет автоматической проверки устойчивости написанного кода к неожиданным входным данным.

**Solution:** После перевода эпика в статус `Completed` автоматически запускать процедуру fuzzing тестирования. Субагент генерирует:

- случайные/граничные входные данные для функций эпика
- невалидные параметры
- edge cases (пустые строки, null, переполнение, спецсимволы)

**Результат:** отчёт сохраняется в `execution/completed/EPIC-NNN/fuzzing-report.md`. Включает:

- список протестированных функций
- найденные краши/неожиданное поведение
- рекомендации по исправлению

**Границы:**
- Fuzzing запускается только после завершения всего эпика, не отдельных тасок
- Покрывает только функции, написанные/изменённые в рамках эпика
- Не заменяет unit-тесты, а дополняет их
- Если найдены краши — эпик остаётся `Completed`, но создаётся новый Task/Bug
